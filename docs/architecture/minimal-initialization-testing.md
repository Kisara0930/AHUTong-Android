# 最小初始化 APK 测试说明

交付目录中的签名 APK 与全部 `.ahup` 使用同一官方信任证书。APK 不内置
基础组件；首次必要下载为共享运行时、原界面运行时、账户及外观组件的依赖闭包。
`component-catalog.json` 是完整清单，`size-report.json` 给出实际字节数。

## 本地市场

1. 在交付目录运行 `powershell -ExecutionPolicy Bypass -File .\Start-TestMarket.ps1`。
   服务器仅绑定本机回环地址，不上传到生产环境。
2. 用 `adb devices` 确认设备；多设备时为以下命令增加 `-s <设备序列号>`。
3. 运行 `adb reverse tcp:8092 tcp:8092`，安装签名 APK，打开安大通。
4. 阅读隐私政策并确认，在原生初始化页填写 `http://127.0.0.1:8092`，读取列表。
5. 选择所需功能并下载安装。必需组件及声明的依赖会自动加入；成功后进入原登录页或首页。

也可把交付目录复制到手机 Download 内的子目录，通过“导入本地组件目录”选择该
子目录。Android 可能不允许授权整个 Download 根目录。导入会先验签；只安装所选
功能的依赖闭包。手机上自行保存的原始文件不会被删除，应用内部的安装暂存包会清理。

## 数据和恢复

- 正式包可覆盖原安装；不要卸载，不要执行 `pm clear com.ahu.ahutong`。
  现有账户、数据库、偏好和插件数据保留，旧存储迁移仍经过原来的迁移组件。
- 中断下载后重新打开初始化页，恢复功能选择并继续安装；完整安装图提交前不会切换
  部分组件。完成后终止进程再启动，检查原登录页、导航和设置。
- 基础运行时启动失败会进入原生修复页。可下载修复版本、导入官方组件、恢复上一组
  兼容组件或明确选择手动重试。数据版本不允许的回滚会被拒绝。
- 功能升级后需要重启以切换类及原生库，进程内不会同时装载两个共享运行时版本。

## 功能验收

检查首页顶部当前/下一节课程、校园卡区域、原有图标和导航、设置及主题。
切换账号后核对缓存和令牌隔离；冷启动后核对登录状态；显式过期仍应要求重新认证。
检查小组件添加、冷启动更新、后台提醒和账号切换后的刷新。相机和内容运行时仅在
所选功能依赖它们时安装；相机权限由实际使用时申请。支付、发送邮件等操作由测试者
按自己的意愿操作。

`size-report.json` 分开统计裸 APK、必要下载、全部可选功能、解压载荷和执行缓存副本。
执行缓存数字是所选组件全部加载后的副本预算；尚未加载的组件实际缓存更小。
实际安装还包括 Android 优化产物、文件系统开销及原有业务数据；升级保留的回滚版本
额外占用空间，不计作首次下载。

## 开发验证

使用 `:host:assembleDebug` 和 `:host:assembleDebugAndroidTest`。原生宿主测试不能链接
共享 SDK 到测试 APK；集成测试通过实际签名 AHUP 的类加载器调用它，以检验混淆后的
真实 ABI。只在可丢弃的模拟器 `com.ahu.ahutong.pluginpreview` 实例运行以下 fixture：

1. `NativePlatformIntegrationTest` 的 `nativePhase=prepare`：安装市场组件。
2. force-stop 隔离预览进程，再以 `nativePhase=verify` 验证原登录页和唯一运行时。
3. `NativeRuntimeBehaviorTest` 的 `runtimePhase=components`：验证实际组件、JNI、资源、
   原生 APK 小组件模板及后台调度桥接。
4. 分别执行 `runtimePhase=session_prepare`、force-stop、`runtimePhase=session_verify`：
   验证会话恢复、原首页课程/校园卡、过期状态以及两个测试账号的令牌隔离。

宿主、组件和市场必须匹配同一构建。已经发布的组件版本不可用不同字节覆盖；本地测试
重建同一版本后应使用新的隔离市场与预览数据，正式升级应增加组件版本。
